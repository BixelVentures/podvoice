## Minimal wire evolution — proposed closed v2 of existing playback response

Keep the existing playback route/service owners. Use versioned closed response (v1 readers must reject v2, not reinterpret it). Exact root fields: `ok,schema,bootId,roomId,configEntryId,status,provider,actualOutput,expectedBinding,reason`. status is observed/empty/unavailable. reason is null or source_unavailable/source_stale/invalid_source. Unavailable never pretends to be empty. HTTP/session denial remains the existing denial path.

`provider` is the existing validated **whole** podconnect.playback.v1 DTO, unchanged, or null for unavailable. Below `provider` is abbreviated in prose only; real examples use the complete fixture DTO generated by backend tests. Observed requires playing/paused and valid item; empty requires fresh no_active_playback with item=null,target=null. Fresh provider content may be visible even when actualOutput is null; then label provider target as unconfirmed account player, never physical output.

`actualOutput` is null, or exactly `{speakerId,nativeRoomId,homepodId,name}` resolved by server from a unique fresh admitted catalogue row AND exact native route witness. Display name comes from that row, never name matching. Native selection/query_up alone cannot populate actualOutput. Default and NEXT are not fields in this observation; keep their existing configuration/intent owners.

`expectedBinding` is null, or exactly `{id,validUntil}`: a proposed opaque SHA256 identity of the validated provider/native-output custody, not a bearer grant. Server retains/resolves its full witness; frontend only echoes its id and locally expires at validUntil (Unix seconds); server never trusts client expiry. Fingerprint excludes poll_sequence/state/position so unchanged polling does not constantly cancel gestures. Include boot, UI room, account, provider owner_epoch, Spotify target ID, complete native and route identity and item URI; expiry is the minimum original provider and witness deadline. New observed track/native route/owner invalidates old identity. Full exact witness keys already exist:
- native: account_user_id,target_id,room_id,homepod_id,connection_id,session_id,alias_incarnation,alias_registry,alias_revision.
- route: process,device_id,device_incarnation,session_epoch,route_revision,selection_revision,input_generation,input_item_id,input_path_digest.
Do NOT invent missing values, synthesize route revisions, or send writer_fd/pipe proofs to the browser. expectedBinding may exist with zero allowed controls: it establishes expected observation, not permission.

**Required provider boundary:** before populating actualOutput/expectedBinding, backend owner must confirm or extend the EXISTING passive owner to expose these witness fields and original valid_until independently of control claim. Current inspected source proves their existence on room-control observations only. If passive owner cannot provide them, return actualOutput=null,expectedBinding=null; do not derive proof from catalogue or provider metadata. This missing provider contract must be resolved to meet “any actually admitted speaker,” rather than shipping another fallback as completion.

## Lifecycle and race requirements

- Selection changes NEXT only. Start pending is intent; observation determines resulting item/output.
- External start/pause/output change follows the same provider+native snapshot join; no UI action receipt required for observation.
- Join exact account/target/owner and consistent snapshot identities; recheck after every await. Mismatch is no witness, not inferred association. Do not hold a global media lock for sequential discovery of every speaker.
- Validate source timestamps/age <= existing15000ms; preserve original expiry across reads. Reject regressing poll sequence in same epoch. Owner restart clears old witness/offers, then allows fresh epoch observation.
- Empty clears active playback only after valid fresh provider no_active_playback; unavailable may retain clearly stale prior display within same custody but disables effects. Account/boot/scope revocation clears custody immediately.
- Control pending captures expectedBinding; output/track/owner change cancels unused offers and prevents stale send. In-flight effect becomes known receipt or unknown, never resent. Position-only poll does not invalidate controls or animate whole player.
- Observation readiness, native output witness, executable action availability, and transport connectivity are separate facts. No “offline” label for mere missing route/control readiness.
